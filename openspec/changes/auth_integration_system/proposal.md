# پیشنهاد سیستم (Proposal): سیستم یکپارچه احراز هویت، ثبت‌نام و مدیریت نشست‌ها

## ۱. مقدمه و هدف (Objective)
هدف از این طرح، مستندسازی و تدوین معماری مفهومی سیستم جامع احراز هویت، ثبت‌نام، مدیریت نشست و خروج کاربران است. این سند جریان داده (Data Flow)، رفتارهای تجاری، تعاملات شبکه با APIها و ماشین وضعیت مسیریابی (Routing State Machine) را به صورت مستقل از فریم‌ورک و کتابخانه‌های خاص مشخص می‌کند تا پیاده‌سازی نهایی کاملاً منطبق بر استانداردهای مهندسی نرم‌افزار و معماری تمیز باشد.

---

## ۲. اهداف تجاری و نیازمندی‌ها (Business Goals & Requirements)

### ۱.۲. استراتژی مدیریت نشست و توکن‌ها (Session Management)
* **تفکیک مسئولیت توکن‌ها:** 
  * توکن تمدید (`refresh_token`) نباید در بدنه پاسخ‌ها (Body) قرار گیرد؛ این توکن از طریق هدر استاندارد کوکی امن (`Set-Cookie`) با ویژگی‌های `HttpOnly` و `Secure` توسط سرور تنظیم شده و مدیریت آن در سطح لایه کلاینت HTTP به صورت خودکار انجام می‌شود. این کوکی در تمام درخواست‌های بعدی، به ویژه در درخواست‌های تمدید نشست و خروج به سرور ارسال می‌گردد.
  * توکن دسترسی (`access_token`) در بدنه پاسخ JSON تحویل داده شده و کلاینت وظیفه دارد آن را برای درخواست‌های محافظت‌شده در هدر `Authorization: Bearer <access_token>` قرار دهد.
* **تمدید خودکار نشست (Automatic Token Refresh):** هنگام دریافت خطای عدم احراز هویت (کد ۴۰۱)، نشست کاربر با استفاده از کوکی موجود تمدید شده و بدون قطع تجربه کاربری، درخواست معلق مجدداً ارسال می‌شود.
* **خروج ایمن (Secure Logout):** با خروج کاربر، نشست در سرور باطل شده و تمام اطلاعات ذخیره‌شده و نشست کاربر در کلاینت پاک‌سازی می‌شود.

### ۲.۲. فرآیند دومرحله‌ای احراز هویت و تایید OTP
* دریافت شماره موبایل معتبر و درخواست ارسال کد یکبار مصرف (`Send OTP`).
* ارسال شماره، کد دریافتی و شناسه نوع دستگاه جهت بررسی (`Verify OTP`).
* مسیریابی هوشمند بر اساس وضعیت پاسخ سرور:
  * **کاربر جدید (`isNew: true`):** دریافت توکن موقت ثبت‌نام (`registrationToken` با طول عمر ۶۰۰ ثانیه) و هدایت به فرم ثبت‌نام.
  * **کاربر موجود (`isNew: false`):** برقراری نشست و هدایت به صفحه تکمیل پروفایل (در صورت `onboarding.required: true`) یا صفحه اصلی (در صورت `onboarding.required: false`).

### ۳.۲. جریان پویای ثبت‌نام کاربر جدید (New User Registration)
* **واکشی اطلاعات پایه (Base-Info):** قبل از پردازش و ارسال فرم ثبت‌نام، دریافت اطلاعات پایه شامل لیست پایه‌های تحصیلی و رشته‌ها از مسیر عمومی بدون نیاز به توکن احراز هویت.
* **جداسازی عنوان و کلید (Key-Value Separation):** نمایش مقادیر کاربرپسند (`value`) به کاربر و ارسال شناسه‌های استاندارد (`key`) به سرور.
* **وابستگی فیلدهای فرم (Dynamic Form Constraints):** حذف یا مقداردهی پوچ (`null`) فیلد رشته تحصیلی برای پایه‌های تحصیلی پنجم تا نهم.
* **اتمام ثبت‌نام:** دریافت توکن‌های نشست و هدایت مستقیم کاربر به صفحه اصلی (`Home`).

## ۳. جریان کلان کاربری (End-to-End User Flows)

```
[ ورود شماره موبایل ] 
         │
         ▼
[ ارسال درخواست کد: POST /auth/send-otp ]
         │
         ▼
[ ورود کد OTP توسط کاربر ]
         │
         ▼
[ تایید کد: POST /auth/verify-otp ]
         │
         ├─────────────────────────────────────────┐
         ▼ (کاربر جدید: isNew = true)               ▼ (کاربر قدیمی: isNew = false)
[ دریافت registrationToken موقت ]           [ ذخیره access_token و Set-Cookie ]
         │                                         │
         ▼                                         ├──────────────────────────┐
[ دریافت اطلاعات پایه: GET /base-info/onboarding ] │ (onboarding.required=true)│ (onboarding.required=false)
         │                                         ▼                          ▼
[ تکمیل فرم ثبت‌نام (اعمال منطق پایه و رشته) ]    [ صفحه تکمیل پروفایل ]       [ صفحه اصلی: Home ]
         │
         ▼
[ ارسال فرم: POST /auth/register ]
         │
         ▼
[ دریافت نشست و ذخیره توکن‌ها ]
         │
         ▼
  [ صفحه اصلی: Home ]
```

## ۴. معیارهای پذیرش (Acceptance Criteria)

- [ ] **مدیریت نشست:** توکن `refresh_token` فقط و فقط از طریق سازوکار خودکار کوکی‌ها مدیریت شود و در هیچ مدل داده‌ای از بدنه پاسخ استخراج نگردد.
- [ ] **هدر مجوزدهی:** توکن `access_token` به عنوان Bearer Token در تمام درخواست‌های محافظت‌شده قرار گیرد.
- [ ] **مسیریابی دقیق OTP:**
  - اگر `isNew == true`: ذخیره موقت `registrationToken` (اعتبار ۱۰ دقیقه) و ورود به فرم ثبت‌نام.
  - اگر `isNew == false` و `onboarding.required == false`: هدایت مستقیم به Home با پاک شدن پشته ناوبری (Backstack).
  - اگر `isNew == false` و `onboarding.required == true`: هدایت به صفحه تکمیل پروفایل/آنبوردینگ.
- [ ] **اطلاعات پایه ثبت‌نام:** لیست مقاطع و رشته‌ها بدون هدر احراز هویت از `/base-info/onboarding` دریافت شود.
- [ ] **منطق رشته تحصیلی:** برای پایه‌های تحصیلی ۵ الی ۹، فیلد رشته تحصیلی ارسال نشده یا مقدار `null` داشته باشد. برای پایه‌های ۱۰ تا ۱۲، انتخاب رشته اجباری باشد.
- [ ] **مکانیسم تمدید نشست:** در پاسخ به خطای ۴۰۱، درخواست تمدید با کوکی ارسال شده و در صورت موفقیت، توکن جدید جایگزین شده و درخواست تکرار شود. در صورت شکست، کاربر به صفحه ورود هدایت شود.
- [ ] **خروج کامل:** در زمان خروج، فراخوانی API ابطال نشست انجام شده، کوکی‌ها و توکن محلی پاک شوند و کاربر به صفحه ورود بازگردد.
